Point your client, keep your code

The official @modelcontextprotocol/client SDK talks to mcp-mock exactly as it talks to a real server. No request interception, no fake transport.

import { Client, StreamableHTTPClientTransport } from "@modelcontextprotocol/client";

const client = new Client({ name: "my-app", version: "1.0.0" });
await client.connect(
  new StreamableHTTPClientTransport(new URL("https://public.mcp-mock.com/mcp")), // the only change
);

const result = await client.callTool({ name: "get_weather", arguments: { city: "Madrid" } });
// result.structuredContent → { city: "Madrid", temperature: 14, conditions: "thunderstorm", … }
// Same call, same bytes, every time, on any machine.

When a test needs a specific answer, the request carries it in _meta — for any tool name, adapted to each revision's format:

await client.callTool({
  name: "get_weather",
  arguments: { city: "Madrid" },
  _meta: { "com.mcp-mock/response": { structuredContent: { city: "Madrid", temperature: 40 } } },
});

And when it needs the server to fall over, a header does it — on any endpoint and transport:

curl -i https://public.mcp-mock.com/mcp -H "x-mcp-mock-status: 429" …
# HTTP/1.1 429 Too Many Requests
# Retry-After: 1

Built for real integration tests

Not a stub — a faithful server, verified in CI against each revision's official schema and the official SDK.

Five spec revisions

2024-11-05, 2025-03-26, 2025-06-18, 2025-11-25 and 2026-07-28, each with its own transport, handshake, vocabulary and error codes. Pin one to see how your client copes.

Validated on the wire

Every message the mock sends is checked against the official schema.json of its revision, and every endpoint is exercised through the official TypeScript SDK.

22 deterministic tools

Real computations (calculate, hash_text, a real PNG…) and a fake world of weather, stocks, users and flights: same arguments, same bytes.

Failure paths on purpose

Every fake-world tool fails on a documented value — city: "Atlantis", user_id: "missing" — so your error handling gets exercised too.

Control from the test

Force a result, a JSON-RPC error, an input_required, a task or a notification script in _meta. Nothing to register, nothing to clean up.

HTTP failures on demand

x-mcp-mock-status forces any status from 400 to 599, with Retry-After on 429, so retries and fallbacks get tested.

The whole 2026-07-28 surface

Stateless requests, multi round-trip elicitation, progress over SSE, cancellation, subscriptions/listen and the tasks extension.

OAuth, opt-in by URL

Everything under /protected/ needs a token. The mock is its own authorization server: metadata discovery, PKCE, refresh tokens, Dynamic Client Registration.

Stateless

Each request carries what its own answer must be: identical on a laptop, in CI, or behind a load balancer. Snapshot-friendly by design.

Zero setup

Use the free public instance at public.mcp-mock.com, or run your own with one Docker command. A /health endpoint reports the running version.
